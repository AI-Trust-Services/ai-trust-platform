# 03 — Publish the image (push → CI → GHCR)

*Audience: the app's developer. This is the automated build half.*

After [`02`](./02-application-patch.md) added the files, you commit them to a branch and push. A GitHub
Actions workflow (also generated by the tool) then builds the wrapper image and publishes it to the GitHub
Container Registry (GHCR). No manual `docker build` needed.

---

## 3.1 Commit and push

```bash
cd /path/to/your-app
git checkout -b platform-sso
git add -A
git commit -m "Add Platform-SSO sidecar (generated by prepare-app)"
git push -u origin platform-sso
```

(`platform-sso` is the default branch name; if you passed `--branch`, use that name — the workflow
triggers on whichever branch the tool baked in.)

---

## 3.2 What the workflow does

The generated file is `.github/workflows/publish-image.yml`:

- **Triggers** on `push` to the `platform-sso` branch (and can be run manually via *workflow_dispatch*).
- **Builds** `Dockerfile.platform-sso` (the sidecar-wrapped image).
- **Publishes** two tags to GHCR:
  - `ghcr.io/<owner>/<repo>:sso`  ← the stable ref you register in the Marketplace
  - `ghcr.io/<owner>/<repo>:<git-sha>`  ← an immutable per-commit ref
- It logs in to GHCR using the built-in `GITHUB_TOKEN` (no secret to configure).

Flow:

```
  git push (platform-sso)
        │
        ▼
  GitHub Actions: publish-image
        │  checkout → docker login ghcr.io → build Dockerfile.platform-sso → push
        ▼
  ghcr.io/<owner>/<repo>:sso     (+ :<sha>)
```

---

## 3.3 One-time repository setting (required)

The workflow needs permission to write packages. If the first run fails with
`denied: permission_denied: write_package`, set it once:

> **Repo → Settings → Actions → General → Workflow permissions → “Read and write permissions”** → Save.

Then re-run the workflow (Actions tab → the failed run → *Re-run jobs*, or push again).

---

## 3.4 Public vs private package

By default the published GHCR package is **private**. Two options:

- **Keep it private** (recommended): at Deploy time in the Marketplace you'll tick *Private registry* and
  supply a GitHub username + a `read:packages` Personal Access Token so the platform can pull it. The token
  is used only to pull and is never stored (see [`04`](./04-platform-register-and-deploy.md)).
- **Make it public**: Repo → Packages → the package → *Package settings* → change visibility to Public.
  Then you can leave *Private registry* unticked and skip the token.

---

## 3.5 Confirm it published

1. **Actions tab** shows a green `publish-image` run.
2. **Packages** (on your GitHub profile or the repo's right sidebar) lists the package with the `sso` tag.
3. Optional CLI check (needs a `read:packages` token):

   ```bash
   TOKEN=$(gh auth token)   # or a PAT with read:packages
   BEARER=$(curl -s -u "x:$TOKEN" \
     "https://ghcr.io/token?scope=repository:<owner>/<repo>:pull&service=ghcr.io" \
     | python3 -c "import sys,json;print(json.load(sys.stdin)['token'])")
   curl -s -H "Authorization: Bearer $BEARER" \
     "https://ghcr.io/v2/<owner>/<repo>/tags/list"
   # → {"name":"<owner>/<repo>","tags":["sso", "<sha>"]}
   ```

Once `…:sso` exists, move to the platform side: [`04-platform-register-and-deploy.md`](./04-platform-register-and-deploy.md).
